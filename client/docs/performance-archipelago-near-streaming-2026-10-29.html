Keep nearby terrain ready.
Reuse work before adding concurrency.

Paired test · Staged results · Correctness · Images

In the accepted same-page ABBA test, moving FPS rises from 83.5 to 89.8 (+7.6%). CPU frame time falls from 5.30 to 4.35 ms. Mean near-chunk readiness rises from 97.27% to 99.997%. Peak additional cached terrain is estimated at 50.2 MiB. This is a measured gain on this Firefox fixture, not a general hardware guarantee. Final command reuse produces identical RGBA pixels in the tested frozen view.

Production implementation

  1. Retain clean, unedited standard terrain near the active window. Preload one extra chunk ring at lower priority. Cache up to 96 chunks within a 64 MiB estimate; evict beyond a two-ring margin. The active ownership mask stays unchanged until a chunk is activated. Procedural micro geometry is unloaded outside the active region.
  2. Use up to two terrain workers for active demand and edits, with at most four in-flight plus completed jobs. Only the primary worker performs speculative preloading by default. Start the second worker after the first successful response to avoid overlapping cold module loads. Preserve healthy in-flight work when a worker fails.
  3. Reuse one globally ordered opaque near-terrain render bundle. Keep transparent terrain in the normal globally sorted list. Invalidate on publication, visibility and material changes. This batches command submission; it does not merge vertex buffers, reduce triangle counts, or promise fewer GPU draw calls.

Cache MiB estimates voxel arrays plus CPU and GPU mesh data. It is not measured process memory or VRAM usage; active chunks, worker runtimes, recycled arrays and driver overhead are additional. This cache uses a bounded distance margin, not LRU. Preloading can increase total generated work while reducing visible waiting.

Correctness and excluded attempts

Early 4 × 4 regional bundles changed seven pixels, then four pixels after correcting near/far order. Those candidates were rejected. The final single opaque command list retains global near material/depth order and executes before far terrain bundles. The final batch, scheduled and repeated-reference captures each have zero differences across 3,686,400 RGBA pixels; saved PNG bytes are independently checked by this report generator. This demonstrates equivalence at these poses, not at every possible camera.

The first three runs completed their timing with command reuse disabled, then failed the post-timing candidate pixel check. Their timings remain exploratory evidence for caching and worker count; they are not acceptance evidence for the rejected bundle implementation. Two pre-timing initialization attempts stalled, one with Firefox's empty-worker-source warning. The exact cause is unproven. Sequential worker warmup subsequently reached sampling. A later tab-visibility interruption is excluded from timing conclusions.

The first complete ABBA timing attempt then compared maps while the return-to-origin streaming/fades were still active and reported 3,013 differing pixels. It is retained as paired-unsettled, outside the primary results. The final harness waits for ready near chunks, no far pending work or transitions, and no ownership fades for 120 consecutive frames before pixel checks. The rerun passed both map and near-command RGBA checks. Timed blocks and production renderer code were unchanged.

Regression coverage includes hidden prefetch ownership, cached-mesh activation, wrap seams, cache bounds, authority windows, out-of-order worker results, queue pressure, worker failure, transparency and command invalidation. See the linked validation record for final test and build results.
