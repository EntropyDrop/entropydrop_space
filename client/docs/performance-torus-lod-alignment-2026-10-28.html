Common-detail performance · CPU optimization · Terrain images

Nature, Copper Metropolis and Aether Archipelago use the same original terrain export and torus projection. The common reference retains one-metre source cells on both sides, including the opposite patch. Space's ordinary adaptive LOD is tested separately with the same geometry before and after the candidate optimization.

What is aligned: standard-cell source detail, fixture coverage, camera, 1280 × 720 rendered pixels, 70° vertical FOV, 8-chunk near radius and 576-chunk far radius. Fog is disabled. DH uses horizontal detail 0 and PIXEL_ART vertical quality; all 512 target sections must be uploaded. Space must load all eight finest sources and select only the 1 m mip. This deliberately removes adaptive LOD loss from the common reference. It does not make the two adaptive hierarchies equivalent.

Remaining differences: lighting, color transfer, greedy tessellation, near/far blending, graphics API and application/runtime overhead. The fixture contains eight of 128 zones (6.25% area), and microvoxel ornaments are omitted. Minecraft gameplay physics remain flat. The native benchmark disables flight FOV effects and validates the actual projection matrix at 70°; earlier nominal-70° runs were excluded. Native FPS is uncapped; browser presentation is refresh-limited. A native frame interval and a browser GPU pass span are different metrics and do not establish a renderer speed ranking.

What changes in production

Enable scheduled CPU maintenance; keep tighter idle culling experimental. Across all three terrains, scheduling reduces the distant-update subspan by 80.4–80.9% while stationary and 56.7–72.1% while turning, saving roughly 0.032–0.045 ms per frame. Complete CPU callbacks improve by 1.6–4.1%; presentation remains around 120 FPS. This is a modest CPU improvement with unchanged geometry, not a demonstrated GPU or FPS speedup. Production LOD and cache budgets stay unchanged.

The tighter-culling candidate reduces stationary near-view face submission by about 24–26%, and improves the adaptive profile's measured GPU span by 16–19%. However, the common-detail Nature and Aether near views regress by 5.0% and 11.1%. It stays off by default. GPU block variance is substantial even in controls with unchanged geometry; the maintenance experiment also has mixed GPU spans, so no stable GPU benefit is claimed.

Experiments at unchanged LOD

The first candidate remains experimental because its GPU result varies with detail level. The existing renderer keeps a broad visibility guard so camera motion can reuse visibility maps. The candidate waits for six unchanged camera/frustum updates, then tightens that guard. Any movement restores the broad guard immediately and invalidates cached tests. Source data, selected mips, face colors, lighting and the optional lossy torus-backface filter are unchanged.

Each view uses reference / candidate / candidate / reference blocks. Each block warms for 5 s and measures for 10 s. The adaptive profile also includes a repeatable turning trajectory. GPU values are asynchronous WebGPU pass envelopes, not total application frame time. Positive percentages mean slower. Screenshot differences compare the two Space variants at the same detail.

The separate maintenance profile keeps the original visibility guard and skips repeated batch traversal while resident arena geometry remains unchanged. It resumes work for publication, fading, ownership changes, projection changes and scheduled buffer cleanup. It adds 30 s of steady warmup before measuring. It changes CPU scheduling, with identical selected geometry and images.
