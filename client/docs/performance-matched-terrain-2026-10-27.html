Controlled setup

Apple M1 Pro; Minecraft 1.21.1, Java 21, Sodium 0.6.13, Distant Horizons 3.3.3 and the new spacebench mod. Fabric API is DH's bundled dependency. No content packs, Iris, shaders or unrelated mods are installed in the isolated instance. Existing installations and saves are untouched.

Both renderers use 1280 × 720 actual pixels, no MSAA, vertical FOV 70°, eye (512.5, 96, 512.5), looking north and 18° down, near distance 8 chunks and far radius 64 chunks. Space uses flat projection, medium lighting and no shadows. The map has no fluids, trees, entities, structures or microvoxels. Minecraft's daytime is fixed; the viewmodel is hidden in both captures.

All terrain preparation is excluded. Minecraft used an additional 60-second warmup after validating the already prepared save. Each renderer's comparison uses eight balanced blocks (four samples per variant), with 5 seconds warming and 10 seconds measuring per block. Minecraft was closed before Space sampling. Moving Space views follow ±16 m lateral displacement, up to 16 m forward displacement and ±0.6 radians yaw.

What changed in Space

The existing visibility code preserved every nearby face block inside a 256 m guard because ring projection bends and locally flattens geometry around the camera. Flat projection has no such deformation. It now applies the existing conservative sphere/frustum and normal-cone tests inside that range too, retaining the same motion padding, cached-query guards and terrain coverage rules. Torus behavior is unchanged.

The fixed-view candidate reduces submitted far faces by 66.4% (1,250,379 → 419,659). Camera movement was retested separately. Pixel checks cover the initial view, translated camera, 90° and 180° turns, return view, and restoration of the reference path. All candidate/reference channels are exactly equal in those captures. Unit tests cover cached and uncached paths, stationary switch restoration, and retaining the torus exemption.

The first moving reference block had 115 frames with pending streaming work; later blocks had 9–10. Excluding that first block as a sensitivity check still gives about 17% lower GPU time. Initial unfrozen moving screenshots differed because geometry publication advanced between images; the accepted pixel checks freeze publication only, while ordinary timed frames remain live.

Compare the rendered result

The same ridges and per-block colors align. Space's distant silhouette is visibly coarser in this configuration; Minecraft's fog and shading also differ. Equal source data does not imply equal distant image quality. This single bounded heightfield is a reproducible first control, not a substitute for the three original toroidal terrains with overhangs and islands.

Research that informed the experiment

  • Voxy: hierarchical occlusion traversal combines visibility hierarchy, screen-size refinement and GPU-generated work. Its upstream renderer requires compute and indirect-count capabilities absent from this Mac's OpenGL 4.1 driver. No upstream Voxy FPS is claimed. A community Metal port uses a different cross-API bridge and is not the tested upstream renderer.
  • Distant Horizons: LOD quadtree selects sections and retains parent coverage until child replacements are ready. Section-level selection and frustum rejection differ from Space's smaller face-block lists. Tested release.
  • Aokana (2025) combines shallow voxel DAGs, streaming, Hi-Z and a visibility buffer to reduce memory traffic and overdraw. Its reported gains concern its own scenes and pipeline; copying one culling pass does not transfer those gains to Space.
  • Six Ways to Draw Vangers with WebGPU (August 2026) tests six representations over one data path. It finds that horizon-level views expose coverage and silhouette failures hidden by top-down views. This supports using a shared dataset and eye-level captures before replacing our representation; its fastest measured mesh also carries editing/storage costs.

Rejected candidate and follow-up priority

Grouping 16, 32 or 64 visibility blocks for an extra CPU frustum level was measured on all three existing torus terrains: 144 blocks, 38,774 frames and 6,458 GPU samples, including repeats and identical-code controls. It did not yield a consistent improvement beyond drift, so it remains disabled. Cluster raw summary. The next larger experiment should compare true occlusion rejection against its depth-pyramid and synchronization cost, keeping the source terrain and silhouette quality fixed. Merely increasing grouping or moving a flat scan to the GPU is not the key mechanism of Voxy/Aokana.
